01 — Introduction

How I went about SoccerVision.

Think about everything available to us right now — AI vision APIs, language models, cloud infrastructure, open-source CV models. It's like a box of Legos. Powerful pieces, already built. The job isn't to reinvent them. It's to know which ones exist, understand how they connect, and figure out what problem you can solve by putting them together the right way.

The Task

Explore the potential of using machine learning and AI to analyze videos of soccer matches and extract valuable insights. I wanted to tackle this problem by assembling the right blocks — not building from scratch.

03 — The Problem

Coaches have strong instincts. Data is fragmented.

The current reality
  • Video review is manual and time-intensive — analysts watch hours of footage to find key moments
  • Stats tools give numbers, not context — possession percentages don't explain why the press broke down
  • No connection between what happened on the pitch and why it happened
  • Tactical feedback takes days to prepare; by then the moment has lost its impact
The gap this creates

Coaches know something went wrong. Proving it — and showing players — takes hours they don't have.

The question isn't whether AI can help. It's whether it can be assembled in a way that fits a real coaching workflow.

What success looks like

Not dashboards. Decisions.

Surfaces the 2–3 moments that mattered in a clip
Shows possession flow, not just percentages
Gives coaches something to say in the next training session
Fast enough to use at halftime

Quality matters. Broadcast-quality footage provides the consistent visual conditions needed for reliable detection. Lower-quality video degrades accuracy significantly — this system is optimized for high-quality content.

Keyframe Extraction

The browser uses the Canvas API to pull frames from the video at regular intervals — no full video is sent to the server. Frames are extracted at 1280×720. Higher resolution matters: the ball becomes invisible at half that size.

Parallel Frame Analysis

Claude Vision (Sonnet 4.6) analyzes each frame: player positions, ball location as 0–100 pitch coordinates, team possession, and visible events. Four frames run concurrently — cutting total processing time by 75% versus doing them one at a time.

Camera Calibration

Each frame is mapped to a slice of the pitch. The system estimates which portion of the field is visible and translates screen coordinates to real pitch positions — enabling spatial analysis even as the broadcast camera pans.

Event Review

Candidate moments — potential goals, shots, corners — are pre-flagged using geometry. Claude reviews those specific windows with images to confirm or reject each. Scoreboards are read every frame and cross-referenced: a goal is confirmed the moment the number changes.

Vision Synthesis

Claude Opus (4.8) receives up to 12 key frames alongside all aggregated metrics. It produces coaching insights, an outcome projection (home win / draw / away win), per-shot Expected Goals (xG), and a 2–3 sentence narrative of the clip. The system prompt is prompt-cached so repeated analyses don't re-pay for it.

11 — ML & AI Techniques

Choosing the right tool for each job.

Different stages need different capabilities. The key is matching the right model to the right task — and knowing what each one can't do.

Claude Vision · Sonnet 4.6
Per-frame detection
  • Identifies players, ball, and events from a still image
  • Handles ambiguity — shadows, crowds, unusual camera angles
  • Returns structured JSON: positions, possession, events
High accuracy on context-heavy situations. Slower than pure CV per frame.
Claude Opus · 4.8
Tactical synthesis
  • Sees curated key frames + all numeric metrics together
  • Judges tactical shape, defensive line height, shot quality
  • Outputs coaching insights and Expected Goals estimates
Strongest reasoning model. One call per analysis. System prompt is cached.
YOLO (optional layer)
Dense tracking
  • Tracks players and ball at 15fps
  • Generates high-frequency positional data
  • Runs locally via a separate worker endpoint
Very fast and cheap. But produces coordinates — not meaning. Needs Claude to interpret.
Why a hybrid approach?
Pure LLM

Rich, context-aware output — but too slow and expensive at high frame rates

vs
Pure CV (YOLO)

Fast and cheap — but produces coordinates, not insight

→
Hybrid

CV handles the volume. LLMs handle the judgment. Best of both.

Expected Goals (xG)

xG estimates the probability that a shot results in a goal — based on angle, distance, and defensive pressure. In SoccerVision, xG is vision-grounded: Claude Opus looks at the actual shot frame and estimates chance quality from what it can see (keeper position, defender proximity, body angle at contact). When visual evidence is unclear, it falls back to a positional formula.

12 — Challenges & Validation

What makes this genuinely hard.

01

Latency

Each API call takes 8–15 seconds of network and model time. Running four frames concurrently already cuts total time by 75%. Prompt caching on the Opus synthesis call avoids re-sending the same system instructions on every analysis.

02

Camera Motion

Broadcast cameras pan constantly. A player in the left third of one frame appears in the right third of the next. Camera calibration smooths this — blending position estimates across frames and only snapping on large detected cuts.

03

Event Ambiguity

Not every contact is a shot. Not every raised arm is a celebration. The candidate window system pre-flags likely moments using geometry, then Claude verifies — reducing false positives without losing true events.

04

Scoreboard Reading

Scoreboards are read every frame, but goal synthesis only triggers when the score actually changes — cross-referenced against visual evidence of the ball crossing the line. Pre-clip context is excluded from in-clip goal detection.

How We Validated the Workflow

Each stage has internal checks: events are deduplicated across time and position windows, conflicts between Claude's output and geometry flags are surfaced explicitly, and synthesis insights are grounded in key frames — not inferred from stats alone. The system tags low-confidence events so they can be filtered or reviewed separately.
