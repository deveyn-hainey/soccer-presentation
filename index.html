01 — Introduction

How I went about SoccerVision.

This was a fast task, so I treated it like a realistic early-stage product investigation: understand the users, research what is already possible, assemble proven building blocks, build a working proof of concept, then be honest about what I would validate next with more time.

The Task

Explore the potential of using machine learning and AI to analyze videos of soccer matches, extract player/ball/event data, identify challenges, compare techniques, and explain what insights could be useful in practice.

My Constraint

I did not try to train every model from scratch in a few days. I used available building blocks from the internet, open-source CV models, APIs, and public soccer datasets/docs, then connected them into a demo that shows the product direction.

04 — The Problem

Coaches have strong instincts. Data is fragmented.

The current reality
  • Video review is manual and time-intensive — analysts watch hours of footage to find key moments
  • Stats tools give numbers, not context — possession percentages don't explain why the press broke down
  • No connection between what happened on the pitch and why it happened
  • Tactical feedback takes days to prepare; by then the moment has lost its impact
The gap this creates

Coaches know something went wrong. Proving it — and showing players — takes hours they don't have.

The question isn't whether AI can help. It's whether it can be assembled in a way that fits a real coaching workflow.

What success looks like

Not dashboards. Decisions.

Surfaces the 2–3 moments that mattered in a clip
Shows possession flow, not just percentages
Gives coaches something to say in the next training session
Fast enough to use at halftime

06 — Scope

Know what you're building. And what you're not.

Footage type Standard broadcast TV — most accessible, highest quality
Clip length 1–3 minute segments for the demo
Delivery Upload → analyze → insights
In Scope
  • Player and ball position extraction from sampled frames
  • Optional dense tracking through the local YOLO worker
  • Key event detection (goals, shots, passes, corners)
  • Team identification
  • Performance metrics and confidence flags
  • Coaching insights generated from structured match data
Out of Scope
  • Real-time / live analysis
  • Multi-camera support
  • Biometric data
  • Full 90-minute match analysis
  • Injury risk flagging
Key Assumption

Quality matters. Broadcast-quality footage provides the consistent visual conditions needed for reliable detection. Lower-quality video degrades accuracy significantly — this system is optimized for high-quality content.

09 — Architecture

How the pipeline actually works.

The current app is a hybrid proof of concept: browser frame extraction, vision routes for structure, optional local YOLO preprocessing, and a final synthesis pass for coaching language.

Keyframe Extraction

The browser uses the Canvas API to pull frames from the video at regular intervals — no full video is sent to the server. Frames are extracted at 1280×720. Higher resolution matters: the ball becomes invisible at half that size.

Parallel Frame Analysis

The app can use Claude Vision as a fallback to analyze sampled frames: player positions, ball location as 0–100 image coordinates, possession, and visible events. The client runs bounded concurrency so a short clip can be processed without waiting on every frame serially.

Camera Calibration

The app estimates which slice of the pitch is visible for sampled frames. The optional YOLO worker can go further: detect field keypoints and use homography to produce true pitch positions when calibration succeeds.

Event Review

Candidate moments — potential goals, shots, corners — are pre-flagged using geometry. Claude reviews those specific windows with images to confirm or reject each. The event route also asks for scoreboard reads per supplied frame, then the app synthesizes clip-scoped goals only when the observed score increases after the baseline.

Vision Synthesis

The summary route sends selected key frames and aggregated metrics to the configured summary model. It produces coaching insights, an outcome projection, per-shot Expected Goals (xG), and a 2–3 sentence narrative of the clip, with deterministic fallbacks when the model call fails.

11 — ML & AI Techniques

Choosing the right tool for each job.

Different stages need different capabilities. The key is matching the right model to the right task — and knowing what each one can't do.

Claude Vision · Sonnet 4.6
POC frame interpretation / fallback
  • Reads sampled frames and returns structured JSON
  • Useful for context-heavy cases and quick prototyping
  • Can identify players, ball, possession, and visible events
Strong for interpretation, but not ideal for dense frame-by-frame tracking, stable IDs, or low-cost full-match processing.
Claude Opus · 4.8
Tactical synthesis
  • Sees curated key frames + all numeric metrics together
  • Judges tactical shape, defensive line height, shot quality
  • Outputs coaching insights and Expected Goals estimates
One synthesis call per analysis in the current repo. Best used after deterministic stats and key frames are already prepared.
YOLO (optional layer)
Production path for dense CV
  • Detects players, ball, and referees with the right weights
  • Can generate dense frames at 15fps through the worker
  • Can run locally now or on a hosted GPU later
Fast and cheaper at scale, but quality depends on soccer-specific weights, tracking stability, and calibration.
Why a hybrid approach?
Pure LLM

Rich, context-aware output — but too slow and expensive at high frame rates

vs
Pure CV (YOLO)

Fast and cheap — but produces coordinates, not insight

→
Hybrid

CV handles the volume. LLMs handle the judgment. Best of both.

Expected Goals (xG)

xG estimates the probability that a shot results in a goal. In the current repo, the synthesis model can assign per-shot xG from key frames and visible context; when that is unavailable, the app falls back to a positional formula. With more time, this should be calibrated against a real labeled shot dataset.

12 — Challenges & Validation

What makes this genuinely hard.

01

Latency

Each API call takes 8–15 seconds of network and model time. Running four frames concurrently already cuts total time by 75%. Prompt caching on the Opus synthesis call avoids re-sending the same system instructions on every analysis.

02

Camera Motion

Broadcast cameras pan constantly. A player in the left third of one frame appears in the right third of the next. Camera calibration smooths this — blending position estimates across frames and only snapping on large detected cuts.

03

Event Ambiguity

Not every contact is a shot. Not every raised arm is a celebration. The candidate window system pre-flags likely moments using geometry, then Claude verifies — reducing false positives without losing true events.

04

Scoreboard Reading

The event route reports scoreboard values when legible, but goal synthesis only triggers when the score increases after the clip baseline. This avoids counting goals that happened before the uploaded clip started.

What the POC validates

Each stage has internal checks: events are deduplicated across time and position windows, conflicts between Claude's output and geometry flags are surfaced explicitly, and synthesis insights are grounded in key frames — not inferred from stats alone. The system tags low-confidence events so they can be filtered or reviewed separately.

13 — Evaluation Plan

What I would evaluate with more time.

Because this was a fast task, I focused on proving the workflow. The next step would be a proper benchmark that measures whether each signal is accurate enough for coaches to trust.

Detection Can we find the right objects?

Measure player, ball, goalkeeper, and referee precision/recall across camera angles, jersey colors, lighting, close-ups, and wide tactical shots.

Tracking Do identities stay stable?

Measure ID switches, track fragmentation, missed ball frames, and how well interpolation handles short ball-detection gaps.

Calibration Are positions meaningful?

Compare image-space locations against true pitch coordinates using keypoint homography and labeled pitch landmarks.

Events Are key moments timed correctly?

Benchmark passes, shots, saves, goals, corners, fouls, and scoreboard changes against hand-labeled clips.

Insights Would a coach use this?

Have analysts rate whether the recommendations are specific, evidence-backed, and useful for the next training session.

Operations Can it run at the right cost?

Measure processing time, API cost, GPU cost, failure rate, and whether the pipeline is fast enough for halftime or post-match review.

15 — With More Time

This is the foundation. Here's where I would take it.

The demo handles short clips and proves the workflow. With more time, better data, and hosted infrastructure, I would move from proof of concept to a measurable soccer analytics pipeline.

Better Data

Labeled soccer benchmark

Create or obtain labeled clips for players, ball, referees, pitch landmarks, shots, passes, and goals. Use this to measure real accuracy instead of relying on visual inspection.

Better Model

Fine-tuned detector + tracker

Train or fine-tune a soccer-specific YOLO model, add stronger tracking, and evaluate ID stability across camera cuts and occlusions.

Better Geometry

Pitch homography everywhere

Use field keypoints and calibration data so heatmaps, distance, line height, and tactical shape are based on real pitch coordinates.

Infrastructure

Hosted worker vs local worker

Keep local inference for demos and low cost, but host the YOLO/homography worker on a GPU service when teams need faster turnaround and shared access.

Product

Coach-in-the-loop review

Let analysts approve or correct events, then feed those corrections back into the evaluation set and future model tuning.

Scale

From clips to match library

Extend from 1–3 minute clips to full-match and multi-match analysis: player development, opponent tendencies, and league-wide benchmarking.

The takeaway

The pieces existed. The work was knowing which ones to connect.

SoccerVision is a proof of concept — built to explore whether AI can do more than track, whether it can actually understand what it sees. The answer is yes. The question now is how far that goes.
